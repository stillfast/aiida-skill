# Pilot A/B: does the `aiida` skill improve answers?

- date: 2026-11-15
- model: deepseek-v4-flash (same for all arms)
- tasks: 5 (see `benchmarks/tasks/`), one run each
- transcripts: `benchmarks/transcripts/{baseline,baseline_tools,skill}/`

## Design

Three arms, identical task text, fresh session per task:

| arm | skill installed? | tools allowed? | control sentence |
| --- | --- | --- | --- |
| `baseline` | no | **no** (asked to answer from own knowledge only) | yes |
| `baseline_tools` | no | yes | no |
| `skill` | yes (`$DSH_HOME/skills/aiida`) | yes | no |

The skill catalog was verified to be absent in both baseline arms and present in
the skill arm (the live catalog was checked after moving the symlink).

## Scores (rubric in `benchmarks/tasks/`, weight-normalised, 0–1)

| task | baseline (no tools) | baseline + tools | skill |
| --- | --- | --- | --- |
| t1 config layers | 1.000 | 0.800 | 1.000 |
| t2 build Si builder | **0.000** (used `CalculationFactory("abacus")`, not a real entry point) | 1.000 | 1.000 |
| t3 diagnose partition | 0.667 | 0.833 | 1.000 |
| t4 diagnose SCF 302 | 0.833 | 1.000 | 0.833 |
| t5 batch 20 structures | 0.600 | 0.800 | 0.700 |
| **mean** | **0.620** | **0.887** | **0.907** |
| perfect tasks | 1/5 | 2/5 | 3/5 |
| rubric violations | 1 | 0 | 0 |

Per-task delta vs the honest control (`baseline + tools`):

| task | delta |
| --- | --- |
| t1 | +0.200 (provenance/immutability named) |
| t2 | 0.000 |
| t3 | +0.167 (says "don't modify stored nodes"; locates the dynamic-namespace root cause) |
| t4 | **-0.167** (did not state the "verify convergence before reporting energies" criterion) |
| t5 | **-0.100** (did not name `SubmissionController`; ended with clarifying questions) |
| mean | **+0.020** |

## What the numbers say

1. **Most of the gain is tool access, not the skill**: 0.620 → 0.887. An agent
   that probes the environment (entry points, pseudos, real nodes, log files)
   gets nearly everything right. The skill's SOP says "probe first" — but a
   capable agent does it anyway.
2. **The skill floor is higher, the ceiling is the same.** With the skill, no
   task used a non-existent API (t2 = 1.0) and no task violated a rubric
   (0 violations vs 1). Without tools, the same model hallucinated an entry
   point.
3. **On two tasks the skill arm scored lower** — not because it was wrong, but
   because its answers were longer and more exploratory and the rubric rewards a
   checklist of specific facts. t5 in the skill arm ended by asking three
   clarifying questions instead of closing the loop.
4. **Where the skill visibly changed behaviour**: the skill-arm t2/t3/t4
   transcripts cite real pks (`574597`, `_aiidasubmit.sh`, sibling `574455`) and
   the skill's reference files, i.e. answers were *grounded in this profile*
   rather than recalled.

## Limitations (read before trusting the delta)

- **N = 5, one run each.** A single lucky/missed fact moves the mean by 0.2.
  Repeat or grow the task set before drawing conclusions.
- **Regex judge.** Answers are scored by weighted keyword checks; synonyms and
  different organisation are penalised. Two rubric false positives were fixed
  during scoring (a `must_not` that would match a correct negation, and a
  missing Chinese synonym); both arms were re-scored afterwards.
- **Task selection bias.** t2/t3/t4 come from failures this skill documents, so
  the skill is favoured by construction; t1/t5 are controls.
- **Cost not measured.** Turns, tokens and wall time differ a lot between arms
  and are not in the table.
- **Async side effects.** The tools arms created files/nodes while probing
  (`si_diamond_scf_builder.py`, two `CREATED` CalcJobs); those are cleaned up or
  noted, and they do not change scores.

## Reproduce

```bash
# remove the skill for a baseline arm, then run the task prompts in fresh sessions
mv "$DSH_HOME/skills/aiida" /tmp/aiida-skill.link
# … save each answer as benchmarks/transcripts/<arm>/<task-id>.md …
mv /tmp/aiida-skill.link "$DSH_HOME/skills/aiida"

python benchmarks/score.py --dir benchmarks/transcripts/baseline_tools
python benchmarks/score.py --a benchmarks/transcripts/baseline_tools \
    --b benchmarks/transcripts/skill --label-a tools --label-b skill
```

## Next experiments worth running

1. **Environment-fact tasks** where guessing fails: "yeesuan 的队列叫什么？",
   "本机有 `sg15_14ve_6p_dzp` 这个赝族吗？" — the skill's `06-doctor.py` and
   `versions.yaml` should show a large delta there.
2. **Procedure tasks with a required artefact** (submit a dry-run, produce a
   CSV) scored by executing the artefact, not by reading prose.
3. **Cost-adjusted score**: same rubric, but report score per 1k tokens / minute.
